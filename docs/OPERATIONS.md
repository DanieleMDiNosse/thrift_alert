# Source-local operation (Ubuntu, no LLM and no Docker required)

Run commands from the source-clone root (the directory containing `marketwatch`).
`marketwatch` fixes its own working directory, so absolute-path invocation works too.
Existing `./subitoo` and `./start.sh --dev` still target the source-built Docker stack;
Docker was absent on this host and that stack is **not verified here**.

## Install / reproduce

```sh
uv venv --python 3.12 app/.venv
uv pip sync --python app/.venv/bin/python requirements.lock
uv pip install --python app/.venv/bin/python --no-deps -e ./app
app/.venv/bin/python -m playwright install firefox
cp .env.example .env
chmod 600 .env
```

For source-local operation set DB_PATH=./data/subitoo.db and BROWSER_BACKEND=local
in .env. Use TZ=Europe/Rome, DEFAULT_CHANNEL=ntfy and NTFY_URL=https://ntfy.sh.
Generate a secret topic locally, e.g. `openssl rand -hex 24`; put it in NTFY_TOPIC,
do not share or commit it. On this host a private .env is already configured: do not
replace it with the example. Install ntfy on Android and subscribe to that private
topic by viewing the local file yourself. No secret is printed in this documentation.

No package is installed globally; Firefox is downloaded to the user's Playwright
cache. Do not run `playwright install-deps` or Docker installation with sudo as part
of routine operation. Missing OS libraries require a separately approved host change.

## Configure meaningful searches

Use actual URLs generated by each website; prefer newest-first and narrow results.
One watch uses one native search URL per platform, not a translated universal query.
`examples/connectivity-demo.json` is a **disabled connectivity demonstration**, not
an instruction to monitor Sony cameras or a guarantee that searches have identical
semantics. Wallapop's URL is a bounded API compatibility probe with explicit Rome
coordinates; confirm your own URL/filter semantics in the website before enabling.

```sh
./marketwatch watch add --from-json /path/to/your-watch.json
./marketwatch watch list
./marketwatch watch show 1
./marketwatch watch test 1
./marketwatch watch edit 1 --from-json /path/to/replacement.json
./marketwatch watch enable 1
./marketwatch watch disable 1
./marketwatch watch rm 1 --yes
./marketwatch query list --json
./marketwatch query test 1
./marketwatch runs 1
./marketwatch query retry 1
```

The IDs above are examples: query IDs and watch IDs are separate. `watch show`
lists the group's query IDs. `watch test` performs real requests but no writes or
notifications. Do not edit/remove watch-owned queries independently: query commands
remain backward compatible, but the next watch edit owns their definition.

JSON fields: name, enabled, min_price_eur, max_price_eur, title_include (list),
title_exclude (list), notify_on_price_change (default false), sources (map).
Source fields: search_url, enabled, cron (default `*/30 * * * *`), max_pages (1–3).
Unknown fields and invalid prices/cron/URLs are rejected. Include terms are literal
case-insensitive substrings, ALL required; ANY exclude term rejects the title.
Prices in watch groups are EUR: native non-EUR listings must not be interpreted as
EUR; watch EUR bounds exclude non-EUR listings. Without bounds currencies are retained.
No FX conversion is provided.

First successful source scan seeds silently. A new source or changed URL/filters
gets its own baseline; disabled/re-enabled unchanged sources retain history.
Fetch/schema failures never establish a baseline. A failed source latches to error;
review restrictions and run `query retry ID` only after resolving the cause. There
is no repeated retry/backoff storm. Other sources continue. Default cron is 30 min;
use 15–30 min conservatively, stagger sites, and keep max_pages small. A 60-second
heartbeat is not a 60-second site poll. No instantaneous-alert promise.

New event identity is (marketplace, listing_id), durable across schedule differences,
normal restarts, and query deletion. The first successfully scanning seeded group
owns the alert; later groups record silently. The alert names that group, not an
unverified union of groups that have not scanned. Previously baseline-seen items
are never promoted to global new just because a later group matches. Failed send
remains pending and cannot be hidden by adding another group's baseline.

New queries default to no price-change pushes; set notify_on_price_change=true to
opt in. Migration preserves the old price-change behavior of pre-existing queries.
Price-change opt-in retains upstream per-query behavior; the global durable
new-event guarantee is not a global price-event guarantee.

## Start / stop / inspect

```sh
./marketwatch doctor
./marketwatch notify test
./marketwatch serve                  # foreground; Ctrl-C stops gracefully
```

To run independently of Hermes without touching existing user services:

```sh
mkdir -p data
chmod 700 data
umask 077
nohup ./marketwatch serve >data/monitor.log 2>&1 &
printf '%s\n' "$!" >data/monitor.pid
```

Stop only this recorded process (inspect its command before signalling):

```sh
ps -p "$(cat data/monitor.pid)" -o pid,args
kill -TERM "$(cat data/monitor.pid)"
```

These are operator shell commands, not an installed system service. A reboot does
not auto-start nohup: restart it manually or install a reviewed user timer/service
separately. Do not run Ofelia/cron and `serve` together. `serve` uses a database-local
advisory lock; due-query atomic claims remain in the existing scheduler.

Read logs: `less +F data/monitor.log` (Ctrl-C then q to leave). Listings and history:
`./marketwatch query list`, `./marketwatch listings QUERY_ID`, `./marketwatch runs QUERY_ID`.
No automatic retries after HTTP 403/429; resolve permission/access problems first.

## Backup / restore SQLite

Do not copy only the main DB while writes/WAL are active. Python SQLite backup
provides a consistent snapshot (protect backups, raw data may contain personal data):

```sh
umask 077
app/.venv/bin/python -c 'import sqlite3,time; from pathlib import Path; Path("backups").mkdir(exist_ok=True); src=sqlite3.connect("data/subitoo.db"); dst=sqlite3.connect("backups/subitoo-"+str(time.time_ns())+".sqlite"); src.backup(dst); dst.close(); src.close()'
```

For restore, stop this monitor, preserve current DB plus WAL/SHM in a separate backup,
and restore to a NEW path rather than overwrite raw state. Example:

```sh
app/.venv/bin/python -c 'import sqlite3; from pathlib import Path; p=Path("data/restored.sqlite"); assert not p.exists(); src=sqlite3.connect("file:backups/CHOSEN.sqlite?mode=ro",uri=True); dst=sqlite3.connect(p); src.backup(dst); assert dst.execute("PRAGMA integrity_check").fetchone()[0]=="ok"; dst.close(); src.close()'
```

Set DB_PATH=./data/restored.sqlite in private .env, then run doctor and inspect queries
before starting. Migrations advance automatically: preserve backups before upgrades.

## Testing / maintenance / limits

```sh
app/.venv/bin/python -m pytest -q app/tests
# Opt-in network-only live smoke, also from repository root:
MARKETWATCH_LIVE=1 app/.venv/bin/python -m pytest -m live -q -s app/tests
```

Explicit virtualenv Python avoids global pytest/interpreter contamination. The
root `hermes verify` auto-detects Docker and is not evidence for local deployment.
No Hermes/Pi/Ollama/llama.cpp/GPU/MCP/LLM is used at runtime.

See VALIDATION.md for actual live counts and end-to-end controlled notifications,
RESEARCH.md for pinned-source audit/security/ToS risks, WALLAPOP.md for unsupported
filters. Facebook has no adapter, no login was attempted, and is explicitly unsupported.
Use Facebook's own saved-search/notification UI manually where available. Never
interpret this release as a four-platform system.

The optional original Docker stack gives Ofelia access to docker.sock even with a
read-only bind: this can confer host-level power. The local scheduler avoids that
socket. Never expose the original unauthenticated browser WebSocket to a network.
Do not import untrusted plugins/configurations: this remains a trusted single-user
CLI, not a multi-user SSRF-hardened service. Public ntfy sees alert content; use a
secret topic or authenticated self-hosted server. Exactly-once remote push cannot
be guaranteed if a process crashes after server acceptance but before DB commit;
normal successful runs/restarts are deduplicated, ambiguous delivery is at-least-once.
